## 一句话结论
在只用 EM 做奖励的 GRPO 下，**上下文策略只在需要跨轮拼证据的题上起作用**：丢弃旧证据的 C1（窗口）和 C2（自写笔记，但训练后几乎不写）在多轮题上显著掉分；规则压缩 C3 保住了准确率，同时每步输入比 C0 少 7–20%。只需一次检索的题（HotpotQA 约 74%），四组完全打平。

## RQ1：EM–token 帕累托（`docs/figures/d9_pareto.png`）
| 数据集 | C0 append | C1 window | C2 notes | C3 rule |
|---|---|---|---|---|
| HotpotQA test EM / 每步 prompt token | 0.542 / 1367 | 0.540 / 1179 | 0.528 / 1377 | **0.550 / 1264** |
| MuSiQue | 0.216 / 1748 | 0.204 / 1283 | 0.198 / 1494 | **0.234 / 1450** |
| 2Wiki | 0.656 / 1825 | 0.546 / 1293 | 0.498 / 1492 | **0.664 / 1458** |

- C3 在三个数据集上都处在帕累托前沿上：EM 与 C0 持平或略高（配对检验不显著），token 少 8%（test）/ 17%（MuSiQue）/ 20%（2Wiki）。
- C1 最省 token（比 C0 少 14–30%），在 HotpotQA 上不掉分，在 2Wiki 上掉 11pp。
- C2 既不省 token（笔记 + 最近一轮文档 ≈ C0），在多轮题上又掉分：被 C3 支配。
- 参照（与四组同口径，OOD 含答案别名）：B1（单次检索）test 0.335、MuSiQue 0.068、2Wiki 0.280；B0（无检索）0.116 / 0.018 / 0.252。四组 RL 都远高于两个基线。
- 口径：EM = 训练奖励函数 `compute_score`，OOD 上会把数据集给的答案别名算作正确（实验卡写成了「只对 ground_truth」，已在卡里更正）。只对 ground_truth 的 EM 与 token F1 见实验卡「补充分析 / 答案指标」：三种口径下组间排序一致（2Wiki 只对 ground_truth：C0 0.516 / C1 0.422 / C2 0.380 / C3 0.530）。

## RQ3：差距出在哪些题上（`docs/figures/d9_by_rounds.png`）
按 C0 在该题用的步数分层（多跳需求的近似）：

| | C0 1 步作答 | C0 ≥2 步 |
|---|---|---|
| HotpotQA test | 0.575 / 0.594 / 0.578 / 0.571（n=737） | 0.449 / **0.388 / 0.388** / 0.490（n=263） |
| MuSiQue | 0.204 / 0.208 / 0.204 / 0.236（n=250） | 0.228 / 0.200 / 0.192 / 0.232（n=250） |
| 2Wiki | 0.690 / 0.714 / 0.705 / 0.738（n=210） | 0.631 / **0.424 / 0.348** / 0.610（n=290） |
（顺序 C0 / C1 / C2 / C3）

- 1 步就能答的题四组打平（C1 甚至略高）；差距全部集中在多轮题。HotpotQA 总分看不出差别，是因为多轮题只占约 26%。
- HotpotQA 官方题型：bridge（809 题）C0/C1/C2/C3 = 0.503/0.499/0.486/0.520；comparison（191 题）= 0.707/0.712/0.707/0.675，C1/C2 **没有**掉分。HotpotQA 的比较题一次检索通常就能拿到两个实体；2Wiki 的比较题（如「哪部电影的导演先去世」）要先查导演、再查各自生卒，必须跨轮。所以驱动差距的是**需要的检索轮数**，不是题型本身。2Wiki 启发式题型：选择比较 0.89/0.70/0.58/0.91，是非比较 0.83/0.66/0.69/0.85，组合推理 0.47/0.42/0.40/0.47。
- 失败方式（2Wiki）：用满 5 步 C0 38 / C1 84 / C2 106 / C3 59；没给出 `<answer>` 44 / 91 / 104 / 48。C2 检索历史里有 182 次逐字重复的查询（C0 76 次）：例如问「Ankusam 与 Count Varenne's Lover 哪部的导演先去世」，C2 查完 "Kodi Ramakrishna death date" 转去查另一位导演后，又把同一条查了一遍，步数用完。
- 放宽到 10 步（X1）：检索轮数上升（C3 在 MuSiQue 2.72 → 3.59），EM 变化都在 ±1.8pp 内，组间差距没有拉开——多给步数不能弥补「忘了前面查到的」。

## RQ4：训练动力学（`docs/figures/e0_e3_dynamics.png`）
- **C1 的策略熵持续下降**（约 0.25 → 0.18，其余三组稳定在 0.23–0.26），每条轨迹 prompt 总量下降（约 1750 → 1530），dev 检索轮数 1.59 → 1.41：窗口丢旧证据，多搜几轮不划算，RL 把 C1 推向「少搜、早答」。这解释了 C1 在 HotpotQA 单步题上略高、在多轮题上掉分。
- C0 / C3 后期检索变多（每条轨迹 prompt 1750 → 2100，dev 轮数 C0 1.37 → 1.60、C3 1.36 → 1.73），能保住旧证据的策略在学「多查」。
- C2 每步 prompt 从一开始就和 C0 一样高（约 1400）：笔记段 + 最近一轮文档没有省下 token。C2 有笔记的训练轨迹比例 10.6%（第 1–10 步）→ 2.6–4.4%（第 51–150 步）；D9 中写了笔记的轨迹 EM 反而更低（test 0.29 vs 0.54，步数 2.6 vs 平均约 1.5）——笔记出现在难题上，在只看 EM 的组内比较中被当成坏行为压下去（相关性证据）。后续改进方案见 `docs/experiment_cards/e4_e5_candidates.md`。
- 四组训练 EM 在第 90 步附近同时下跌：四组数据顺序相同，是这一段批次本身更难，不是某组崩溃。
- 零方差组（同题 8 条轨迹全对或全错，GRPO 无梯度；`scripts/rollout_dynamics.py`，`docs/figures/e0_e3_rollout_dynamics.png`）：四组都从约 74–76%（第 1–10 步）升到约 81–84%（第 141–150 步），即每步 64 题里只有约 11 题提供梯度。四组走势一致，不是组间差异的来源，但说明后期学习信号稀疏，与 dev EM 在第 60–80 步后基本走平一致。
- 重复检索率（训练轨迹最后一步 History Actions 中逐字重复的查询占比）：C0 / C3 约 2% → 4%，C2 从一开始就较高（约 3–5%），后期三组趋同在约 4%（C1 只显示最近一轮查询，无法统计）。训练分布内三组差别不大；D9 上 C2 在 2Wiki 的大量重复（182 / 1170）是分布外、需要跨轮比较的题上才暴露出来的。
- C2 有笔记的训练轨迹比例（同一脚本从 rollouts 重算）：10.6%（第 1–10 步）→ 3.0%（71–80）→ 4.4%（141–150），与实验卡记录一致。

## 局限
- 多跳分层用的是 C0 的步数，不是题目自带的难度标签；2Wiki 题型是按问句启发式分的。
- dev 一致性检查 0.508 vs 训练时 0.526（预设 ±2pp 内），新旧评测环境等价性未证实；本文的主要结论建立在 2Wiki 上 10pp 以上、p<1e-7 的差距上，不受影响；HotpotQA 上 1–2pp 的差距不应解读。
- 单 seed；C2 结论限于「只用 EM 奖励、4B、150 步」这一设定。
